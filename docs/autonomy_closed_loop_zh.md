# 单机自主闭环：探索、目标定位与普通救援

本实现是可实际运行的练习场景闭环：机器人从空白 SLAM 地图出发，自主观察和选择探索点，使用 Nav2 行进，从 RGB 相机识别 ArUco 并估计地图坐标，保存地图和目标清单，再自主导航到推导出的救援区，连续停留后完成任务。

官方尚未公布字典、标记尺寸、救援几何和停留时间。`config/practice.yaml` 中的参数只用于开发验证：DICT_4X4_50、ID 23、黑色边框外沿尺寸 0.24 m、沿标记正面法向偏移 0.60 m 的救援区、半径 0.18 m、连续停留 3 秒。这些数值不能作为正式比赛常量。

## 一键运行

```bash
cd /path/to/edgeai_robot_ws
pixi install --locked
pixi run colcon build --symlink-install
./scripts/run_autonomy_demo.sh --gui
```

脚本自行启动仿真、SLAM、Nav2、视觉、速度保护和任务节点。无需提前启动其他仿真实例。省略 `--gui` 可只运行仿真服务器；相机和激光渲染仍需图形驱动。另一个练习目标位置：

```bash
./scripts/run_autonomy_demo.sh --scenario east
```

障碍物背面、初始不可见的目标：

```bash
./scripts/run_autonomy_demo.sh --scenario behind --gui
```

这些场景使用同样的任务代码和参数，只改变测试场景的标记安装位置。任务节点没有场地地图、目标世界坐标或固定路线。默认演示以“至少成功导航到一个探索前沿且确认目标”为阶段交接条件，目的是先验证最小闭环，不宣称穷尽全场探索。搜索预算为最多 16 个探索/补充观察增量目标、1200 秒仿真时间；找到目标即可提前交接。

## 障碍物挡住目标时

目标尚未看见时，机器人只能通过激光建立地图、向安全前沿移动并旋转观察，不能隔墙获得标记位置。确认目标后，NavFn Dijkstra 在全局代价地图中找绕行路径，障碍膨胀层为机器人留出空间；局部控制器根据最新激光代价地图检查预测碰撞并调节速度。独立速度保护节点负责近距离障碍和失联停车，本身不规划绕行路线。

探索路径和目标点距非空闲栅格至少 0.40 m（`practice.yaml` 的 `exploration_clearance_m`）；整圈旋转观察另要求实际车体位置的已知空闲间距至少 0.60 m（`observation_clearance_m`）。空间不足时记录 `observation_deferred` 并继续通行建图，不在窄处主动执行整圈观察。巡航速度为 0.10 m/s，障碍膨胀半径仍为 0.60 m，到点容差为 0.10 m。

模型驱动轮轴位于 `base_footprint` 前方 0.0875 m。自主演示将 Gazebo 的原始轮式里程计/TF 分别桥接到 `/odom_raw`、`/tf_raw`，由 `drive_odometry.py` 把轮轴积分位姿和速度换算成车体参考点的 `/odom` 和 `odom→base_footprint`，并传播协方差。Nav2 在实际驱动轮轴坐标系 `drive_axle` 下控制，使用包含停车保护区的偏置矩形轮廓与 0.05 m 额外边距（大于 5 cm 栅格的半对角线），局部代价地图以 10 Hz 更新，避免误把车体中心当成物理转动中心。任务记录的目标、探索间距和救援区仍以车体参考点为准，发送给 Nav2 的目标会按期望航向平移到轮轴坐标。

此修正只启用于自主演示；普通 `start_sim.sh` 和单机基线默认保留原始里程计接口。它不读取真值、不改变物理模型，也不消除打滑、碰撞造成的轮式里程计误差。0.40 m 通行间距仍是保守开发配置；两个 0.75 m 门口不属于本次通行验收范围。

`behind` 场景把标记放在横向障碍物北侧：起点到标记的视线被实体障碍遮挡，起点到救援区的直线也被阻挡。独立验收器检查这两个前提、真实轨迹绕行偏移、机器人轮廓与障碍间距，以及最终连续救援停留。轨迹图中的红色虚线只是验收器绘制的被阻挡直线，不输入导航器。`target_confirmed` 事件记录第一次视觉确认时刻，便于核查机器人走到哪里才看见目标。

激光扫到某一区域不等于相机已经看清该区域。对已解码、通过重投影/深度/法向检查但最短边只有 10–22 像素的标记，感知节点只发布 `/autonomy/observation_hints` 临时观察线索。任务尝试移动到其正面约 1 m 的已知安全区域，仍沿安全栅格路径分段移动并交给 Nav2；无法到达或已经尝试过则继续前沿搜索。线索 120 秒后过期，**不加入确认目标，不触发救援**。确认条件仍要求最短边至少 22 像素、至少 3 次有效观测及原有几何检查。`marker_observation` 导航和 `observation_viewpoints_selected` 事件记录这一过程。

如果没有可选激光前沿且仍未确认目标，机器人还会在已知空闲区域内，选择靠近已建图障碍表面、此前未观察过的安全位置，进行 `surface_observation` 补充观察。它可以经过已访问的通路去往新的观察位置，仍受总搜索预算约束；当前没有严格的全场相机覆盖完成判据。

如果没有足够宽的可通行路径，或探索预算耗尽仍没有看到目标，当前任务会停止并记录失败；不会把未知区域当作通路，也不宣称可以解决任意迷宫、封闭目标或动态障碍。

脚本使用 ROS Domain 72、仅本机发现和独立 Gazebo partition。文件锁阻止同一用户同时启动多个此类演示。按 Ctrl+C 终止，进程会自动清理；速度保护节点在命令、LiDAR 或任务心跳超时后发布零速度。

## 模块和数据流

```text
/odom_raw → 轮轴/车体参考点修正 → /odom + TF
/scan + /odom + TF → SLAM Toolbox → /map + map→odom
                                      ↓
                         探索前沿选择 → Nav2 NavigateToPose
                                      ↓
/camera/image + camera_info + depth → ArUco/PnP → 时间戳 TF → 目标融合
                                      ↓
                    冻结地图/目标 → 普通救援分配 → Nav2 → 连续停留
                                      ↓
                              事件日志、结果与验收
```

源码在 `src/edgeai_autonomy/`：

- `geometry.py`：在未知/空闲边界聚类，分割大边界；从已知空闲、具有足够间距并与当前机器人连通的栅格中选择观察点。已到过或尝试过的探索目标会被排除，但允许再次经过公共通道中的中间点，以到达新的前沿。沿已知安全栅格路径最多选取约 0.9 m 的增量目标，再观察和重规划，避免一次朝未知阴影边缘行进过远。
- `mission.py`：等待 Nav2 生命周期激活，控制自主旋转观察、前沿导航、阶段交接、普通救援及失败处理。运动通过 Nav2 actions 发起，没有人工中间航点。
- `detector.py`：OpenCV ArUco 检测和 IPPE PnP；使用已知实体尺寸估计相机坐标位姿，检查重投影误差和可用的同步深度数据，再用图像时间戳的 `map→camera_optical_frame` 变换到地图坐标。按标记 ID 融合多次观测，保留位置、完整四元数、法向、观测次数和离散程度。
- `drive_odometry.py`：依据 URDF 的轮轴偏移校正轮式里程计和 TF；Nav2 使用 `drive_axle`，感知、SLAM 与救援判定继续使用原车体参考点。
- `guard.py`：唯一向 `/cmd_vel` 发布的自主系统节点。Nav2 控制器和行为服务器只发布 `/cmd_vel_nav`；保护节点限制速度、检查 LiDAR 中靠近机器人轮廓的障碍，并在输入或任务心跳超时时停止。
- `config/nav2.yaml`：NavFn Dijkstra 全局规划和 Regulated Pure Pursuit 跟踪；增加行为树服务应答等待，适配传感器渲染时的调度延迟；使用此机器人的尺寸、低速限制、激光障碍层和膨胀层，禁止全局规划穿越未知区域。
- `config/slam.yaml`：独立于官方基线的自主运行配置，允许低速移动及旋转时更新，避免某些 Jazzy 构建中仅按平移筛选扫描导致原地旋转不更新。
- `demo.py`、`acceptance.py`：测试场景生成、进程管理、独立验收。**只有测试器读取 Gazebo 真值和场景坐标；真值不输入感知、SLAM、规划或救援判定。**

任务允许在救援阶段继续运行 SLAM，用于本次连续会话的定位和避障。当前没有在交接时重启 AMCL、重定位机器人或恢复断电后的任务；不能把它视为已完成正式比赛交接流程。

## 连续停留与输出

Task 1 交接时保存地图和确认过的目标列表；后续新发现目标不会自动加入本次救援。后续观察旋转如果被 Nav2 中止，会记录 `observation_incomplete`；已有确认目标时仍可进入救援，没有目标时继续寻找观察点。初始观察 action 失败则终止任务；因空间不足而跳过初始旋转时仍可继续寻找可通行探索点。普通救援点由保存的标记位置和正面法向计算，不是标记中心本身。

Nav2 成功后，任务节点检查地图坐标位置在区域内、里程计新鲜且速度接近零。满足条件才开始计时；中途离开区域、运动或数据过时会清零重新计时。超时或导航失败均记录失败，不冒充完成。

结果写入新的 `artifacts/autonomy_日期_时间/`：

- `run.json`：运行时间、Git 状态、锁文件哈希；同时保存本轮三份配置副本。
- `mission.json`：最终状态、任务配置、目标、救援点、阶段事件和地图坐标轨迹。
- `events.jsonl`：探索、导航、交接、分配、停留及完成/失败的逐条事件。
- `targets.json`：Task 1 结束时冻结的统一目标列表。
- `map.yaml`、`map.pgm`、`map.png`：交接时导出的占据栅格地图。
- `marker_23.png`、`perception.json`：带检测框的真实相机图像及融合结果；`camera_*.png` 用于复查观察过程。
- `evaluation.json`、`REPORT.md`：独立真值核验，包括目标定位误差、法向误差、实际连续停留位置和障碍间距。
- `trajectory.png`、`ground_truth.csv`：Gazebo 真值和 SLAM 估计轨迹。
- `.log`：各节点与导航栈日志。`fixture.json`/`practice.sdf` 是测试器使用的场景记录。

成功退出码为 0，任务失败或验收未通过为 1。验收要求完成前沿导航、保存地图和目标、定位误差小于 0.15 m、法向误差小于 20°、真实机器人在练习救援区中连续停留，以及保守机器人矩形轮廓不与场景障碍重叠。阈值均为本项目开发标准。

## 依赖与检查

Pixi manifest/lock 已增加 Nav2、OpenCV 和 SciPy。`setuptools` 限制为 `<80`，以兼容当前 colcon 的 `develop --editable` 构建方式。

```bash
pixi run bash -c 'source install/setup.bash && python -m unittest discover -s tests -v'
```

测试覆盖丢失控制命令/传感器/心跳时停止、速度限制、激光安装偏移与轮廓障碍停止、规划与保护区几何一致性，以及前沿/观察线索导航不能跨墙或穿越未知区、访问区域排除、相机光学坐标和 PnP 到地图坐标的变换、救援区法向偏移、验收器的旋转矩形重叠和视线遮挡检测。完整任务则通过实际仿真验收。

## 当前范围

已实现单机器人、单普通目标的最小闭环。尚未实现全场探索完成判据、多个目标的任务优化、双机/四机协作、协作救援、LLM、正式机器人接口和硬件校准。场景目前是静态环境；临时障碍会进入局部代价地图，但没有完成动态障碍和复杂通道的系统验证。已知轮式里程计与实际位姿仍会因滑移不同，必须依据 SLAM 与独立测试结果判断效果。

背面目标轮验证了起点视线被遮挡、直达救援区的路线被实体障碍阻挡。机器人最终从障碍左侧绕到北侧，在世界坐标约 (-1.576, 1.734) 首次确认标记，随后导航救援；未向任务传入该坐标。8 次探索导航及观察旋转全部成功，没有失败导航或提前中止观察。任务连续停留 3.001 秒；独立真值采样覆盖约 2.969 秒，位置不动且始终在救援区内。保守机器人轮廓全程没有与障碍重叠。

路径仍包含探索和多次旋转，真实累计行程约 13.03 m，不能当作已优化的最短救援路径。补充观察及低清晰度线索导航已经实现并有针对性单元测试；本次成功轮通过正常前沿探索完成发现，未触发这两条补充支路，因此不把该轮作为它们的完整仿真验收。

14 项单元测试通过。此前 `162139` 轮因规划/保护间距不一致而锁停并中止；`162716`、`163624` 轮无障碍重叠，但因视觉观察不足未完成目标确认，失败日志保留。该版本的成功结果以上表为准。动态障碍、狭窄通道、全部相机补充观察分支和多次随机重复试验仍需进一步验证。

## 房间通行与最新回归（2026-10-30，2026-11-10 核对）

当前参数为 0.40 m 通行间距、0.60 m 整圈观察间距，使用轮轴参考点、偏置矩形轮廓和 0.05 m 轮廓边距。修复了已访问中间点阻止返回公共通道的问题。

房间场景 `autonomy_20261030_120813` 通过 8/8 项验收，13 次探索导航全部成功，进房救援完成，目标定位误差 0.0098 m，最小真值障碍间距 0.0675 m。背面目标回归 `autonomy_20261030_161431` 通过 7/7 项验收，目标定位误差 0.0333 m。两轮均连续停留 3 秒且无真值轮廓重叠；20 项单元测试通过。详见 [房间实测记录和轨迹](competition_rooms_review_zh.md)。两个 0.75 m 门口、全场覆盖和多机协作仍未完成验收。
