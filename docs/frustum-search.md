# 未找到目标时的视锥候选点

默认中期搜寻还启用 [RGB-D 疑似目标搜寻](suspected-target-search.md)：并行感知、串行运动，先完成当前疑似面板有效方向，再继续本模块候选。

只在救援前找不到有效目标、进入再搜寻时启用。正常前沿探索、目标定位和救援终点计算保持原来的接口。

## 模块边界

- `frustum_search.py` 是不依赖 ROS 的评分模块。输入普通占据栅格、相机模型、可行 XY 候选和配置；输出 XY、yaw、收益及评分。不读取目标 ID、仿真真值，不创建导航客户端。
- `search_candidates.py` 是小型适配器：复用原来的 `observation_positions` 净空/连通候选池，从 CameraInfo 和静态 base→optical TF 构造相机模型。相机内参或安装变换不可用、存在未校正畸变或视锥内没有样本时，明确记录原因并回退到原有空间分散策略。
- `target_research.py` 只取下一个候选位姿，执行现有 NavigateToPose 和完整 Spin，并反馈成功转圈后的实测位置。取消确认、重试、预算及目标发现后转入救援仍由原执行层处理。

## 评分与覆盖

在已知栅格上按 `sample_step_m` 采样潜在目标区域，在 `heights_m` 指定的高度上用完整针孔相机模型判断水平、垂直视场和有效距离。占据格和未知格阻挡视线；被直接看到的第一个占据格可以作为观察对象，遮挡近似来自二维激光地图，不是三维深度建图。

同一 XY/高度还按“从潜在目标看向相机”的方向分桶。一个区域从西侧观察过，不会自动消除从东侧观察的收益。给每个位置枚举若干车身朝向，选择：

`score = gain_m2 / (1 + travel_weight * 直线距离 + turn_weight * 朝向变化弧度)`

`gain_m2` 为按高度样本归一化的新增方向覆盖代理面积，不是测得的可识别面积或目标不存在的概率。导航是否真正可达仍由 Nav2 检查；路径代价在本版用直线距离近似。

仅完整转圈成功且有新鲜配对位姿时才更新几何覆盖。生成候选、导航失败、部分转圈及取消均不提前增加覆盖。每次完成转圈后，以已更新覆盖重新选择剩余位置和朝向。仅在本次再搜寻内保存覆盖，不借用探索阶段未记录的相机历史。

候选朝向用于视锥评分及诊断参考。按当前导航规则，所有非最终救援点只检查 XY，规划器使用路径末段朝向，因此不会为该候选朝向单独做终点对准；抵达后仍保留现有完整转圈。本版不承诺减少旋转次数。

## 配置

默认中期配置 `src/edgeai_navigation/config/midterm_single_rescue.yaml`：

```yaml
search_frustum:
  enabled: true
  candidate_pool_size: 24
  yaw_samples: 8
  direction_bins: 4
  sample_step_m: 0.20
  max_samples: 2500
  near_m: 0.25
  far_m: 2.5
  heights_m: [0.20, 0.35, 0.50]
  travel_weight: 0.5
  turn_weight: 0.15
```

设置 `enabled: false` 即恢复原来的选点方式。一般开发场景 `normal_rescue.yaml` 默认关闭；中期场景默认开启。总访问数量、导航/转圈超时、重试和搜寻预算继续使用原来的 `search_*`、`navigation_*` 参数。评分池大小不是完成访问数量。

相机模型由 `/camera/camera_info` 的 K、分辨率和静态安装 TF 得到，不硬编码相机视场角。零畸变/校正后的 CameraInfo 才参与评分。高度列表是可配置的潜在目标高度先验，不包含 S1/C1 真值坐标。

## 性能与限制

只在搜寻入口生成一次有上限的候选/朝向特征，不订阅图像或点云、不建立第二套三维地图。后续选点只做集合差与评分；成功转圈后按实际位置更新覆盖。地图扩大时不会高频重算。使用搜寻开始时的地图快照；若发生大幅 SLAM 修正或动态障碍，Nav2 会检查实际接近路径，但几何收益可能过时。

二维遮挡可能将低于相机的障碍也视为遮挡，无法精确描述悬空物、透明物或标记表面法向；已覆盖不代表一定能解码，也不能替代“解码但未定位”的主动定位逻辑。此功能不放宽感知定位门限。

## 日志和验证

- `SEARCH_FRUSTUM_READY`：实际样本数、候选位置数、高度/距离范围及初始化耗时。
- `SEARCH_FRUSTUM_FALLBACK`：相机模型不可用等回退原因。
- `SEARCH_CANDIDATE`：实际选出的 XY/yaw、`gain_m2`、`score`、当前覆盖键数。
- 每次 `search_attempts` 的 `candidate` 字段保留同样信息，便于关联实际导航结果。
- `SEARCH_COVERAGE_SKIPPED`：转圈完成却无新鲜位姿时，不计覆盖。

纯计算测试：`python3 tests/exploration/test_frustum_search.py`。实际 ROS 动作/服务回归测试位于 `tests/exploration/test_rescue_ros.py`，包含带相机内参和安装 TF 的候选→转圈→发现目标→救援流程。

2026-11-04 验证：7 项视锥计算测试、7 项 ROS 测试（包括原流程回归与相机不可用回退）通过，导航包构建通过。运行 `20261104-222209-185-domain86` 使用实际相机内参/安装 TF 生成 11 个位置×8 个朝向、594 个空间样本，视锥特征预计算约 142 ms；第一个观察点导航超时一次后重试成功并完成转圈，第二个点接近期间定位到 S1，确认取消后进入救援，最终结果 success=true。此单次功能验证不是与旧策略的效率基准对照。
