# 建图期间同步目标探测与定位：接入准备

2026-10-29。第一阶段对象为比赛 ArUco 目标；普通物体检测不在首阶段范围。
此文保留分阶段接入设计；首版被动检测节点现已实现，见 `src/edgeai_perception/README.md`。
深度校验、完整朝向融合和主动视角补扫仍为后续步骤。

## 已具备的输入

- Gazebo RGB-D 相机：640×480、30 Hz、水平视场约60°。
- 桥接话题：`/camera/image`、`/camera/camera_info`、`/camera/depth_image`。
- 相机光学坐标：`camera_optical_frame`，x右、y下、z前；URDF有固定外参。
- `/tf` 提供机器人运动，SLAM 提供 map→odom。
- 开发标记：DICT_4X4_50、黑色标记边长0.20m、面板0.24m。
- 当前依赖：系统OpenCV4.6有cv2.aruco，但无ArucoDetector类；cv_bridge、message_filters、tf2_ros可导入。
- 若启用EDGEAI_DISABLE_RGBD_CAMERA则相机及桥接被移除；感知启动检查必须明确报错。

规则书V0说明字典、标记物理尺寸、安装方式和类型映射另由技术文档确定。
当前仿真设置不能写成正式比赛标准。20cm与24cm不能混用，否则位置尺度产生系统误差。

## 模块和数据流

新增独立 `edgeai_perception` ROS包；与探索节点并行运行，第一阶段不派导航任务。

图像+CameraInfo → OpenCV ArUco角点/ID → PnP候选位姿 → 重投影与深度校验
→ 图像时间戳下TF变换 → 同ID多次观测管理 → RViz显示、关键事件和结构化结果。

使用OpenCV现成检测及solvePnP，适配4.6旧接口和较新ArucoDetector接口。
采用平面方形PnP时严格遵守物点角点顺序、坐标定义，处理正深度和多解问题。
深度作为同步校验：核对RGB与深度对齐、深度encoding及米/毫米单位，不混用无效值。
先完成纯RGB已知尺寸PnP闭环，再接深度校验，避免同时引入多种坐标误差。

## 坐标和时序

定义 T_A_B 把B系点变换到A系：

    T_map_marker(t) = T_map_camera_optical(t) * T_camera_optical_marker(t)

t必须来自图像header，不能使用收到回调的时刻或任意最新TF代替。
CameraInfo的分辨率、内参、畸变模型须匹配当前图像。校验header frame与URDF optical frame。
TF不可用、图像过期、内参无效时跳过并记录原因，禁止把不同时间的位姿拼在一起。
图像队列采用只处理最新帧、有限长度；首阶段处理频率5Hz，独立于相机30Hz。

## 目标记录

每个ID记录：候选/已确认/过期状态、首末观测时间、有效观测次数、原始相机观测、
图像时刻机器人位姿、重投影误差、距离、地图位姿及估计不确定性。
多帧确认、离群值拒绝、距离和斜视角门槛可配置；阈值先通过标定场景测量确定。
不能把连续高相关帧简单当作独立证据而过分缩小协方差。
保留原始观测和时间戳，以便SLAM回环后重新处理；不直接永久平均所有历史map坐标。
仅应用当前map→odom刚体修正不能保证消除非刚性位姿图优化误差，最终精度需独立评估。
未知ID仍可记录，类型映射为unknown；ID→类型与检测字典分开配置。

## 输出与观察

计划接口：
- `targets/observations`：带时间戳、ID、原始相对位姿和质量的单次观测。
- `targets/estimates`：按ID聚合的目标位姿、状态与不确定性。
- `targets/markers`：RViz MarkerArray，区分候选、确认与过期，显示ID和误差指标。
- 可选限频标注图像：用于核对角点与ID，不默认保存全部视频。
- `perception.log`和统一events日志：首次发现、确认、异常拒绝、TF失配和估计跳变。
- 每轮结果写入该轮测试目录，遵守已有存储清理策略；不持续累积每帧图像。

## 真值边界和验证顺序

检测配置只能读取字典、标记尺寸、相机参数及可选ID类型表。
`targets_competition.yaml`中的目标世界位姿只由仿真和独立评估器使用，不能给检测器。
map系与Gazebo world系并不默认相同，评估必须通过独立登记的初始变换对齐。

1. 单个静止标记：确认图像可见、ID、正向/左右轴、距离尺度，分离标记贴图朝向问题。
2. 同一目标多距离和多角度：测重投影误差、相对位置偏差和拒绝率。
3. 机器人平移/旋转：同一目标map位置应保持稳定，检查图像/TF时间匹配。
4. SLAM回环：核对历史目标的位置更新及不确定性，不只看画面是否平滑。
5. 完整探索：检测召回、误报、确认耗时、各目标位置误差和95百分位、RTF与CPU变化。

首阶段只做被动检测。前沿探索依赖360°雷达，而相机仅约60°视场：
地图覆盖不保证目标全部被看见。第二阶段再增加“地图已知但目标观测不足”的视角补扫，
由任务策略统一请求Nav2，避免感知节点直接发布cmd_vel或与探索抢占控制权。
救援停留点由目标朝向推导，是后续任务，与标记中心定位结果分开管理。
