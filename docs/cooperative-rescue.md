## 任务流程

1. 两台机器人从本轮开始就存在。robot2 停在初始区，保留里程计，不参与建图；robot1 探索、识别目标并完成 S1。
2. S1 独立连续停留判定成功后，停车、保存最终地图和该地图坐标下的目标清单。不能只使用 S1 导航返回成功作为交接条件。
3. 停止 robot1 的建图节点，启用一个共享静态 map_server；robot1 和 robot2 各自使用 AMCL 在同一地图定位。robot1 用停止建图前的位姿作为初始化，robot2 用起始相对位姿推算的粗略位姿初始化。
4. 两机定位通过后，为 C1 生成两个可达且互不冲突的停车位，同时派发两个导航目标，各自检查结果并有界重试。
5. 在同一仿真时刻检查两机 base_footprint 到 C1 中心的水平距离；两者同时不超过 0.7 m、连续 10 s 才成功。任一越界、数据过期、时间回拨或定位失效，重置共同计时。

## 坐标和定位

为兼容现有单机入口，robot1 保持根命名空间，robot2 使用独立前缀。统一 TF：

```text
map -> odom -> base_footprint
map -> robot2/odom -> robot2/base_footprint
```

每个 map→odom 只能有一个发布者。交接时停止 SLAM 发布后才能由 AMCL 接管。robot2 等待期间仅发布基于初始相对位姿的动态粗略变换，用于 RViz 显示；启动 AMCL 前停止该发布，定位门槛仍要求 AMCL 位姿与激光匹配，不把粗略 TF 当作定位成功。

初始变换定义：T_A_B 将 B 坐标转换到 A 坐标。保存 robot1 建图开始时的 T_map_base1_start，以及粗略的 T_base1_start_base2_start，则：

```text
T_map_base2_start = T_map_base1_start × T_base1_start_base2_start
```

若 robot2 等待期间移动，用其 odom 中从启动到交接时的相对运动继续传播。不能使用 robot1 完成 S1 时的当前位置乘以“起始相对位置”。粗略平移、朝向及不确定度由配置给出；发布 PoseWithCovarianceStamped 到各机 initialpose，由 AMCL 使用本机激光修正。

定位门槛至少包含：TF/激光/里程计新鲜、位姿持续稳定、合理协方差，以及激光与静态墙体匹配度。协方差小不单独视为定位正确。定位不收敛时执行有净空检查的短旋转/小幅移动，预算耗尽报告定位失败，不直接开始救援。

双机单机建图入口已启用 `fleet_scan_filter.py`：`/scan` 保持原始激光，`/scan_slam` 仅供 SLAM。依据初始相对位姿与两机里程计，在第一台 odom 帧估计第二台的矩形车身范围；范围内端点标为 NaN，不补造遮挡后的自由空间。缺少新鲜里程计/TF 时暂不向 SLAM 转发该帧，避免无过滤回波污染地图。导航和 AMCL 始终保留原始激光，两机仍将彼此作为动态障碍。

过滤参数在 `config/fleet_scan_filter.yaml`，`bounds` 为第二台 `base_footprint` 下车身边界，`margin_m` 默认 0.15 m；粗略相对位姿统一读取 `cooperative_rescue.yaml`，不依赖 Gazebo 真值或 SLAM 输出，避免首次建图的 TF 循环依赖。当前适用于第二台建图期间停放的双机模式，不能保证大幅初值误差或长期里程计漂移时仍完全遮罩。

全局代价地图必须同时启用 `static_layer → obstacle_layer → inflation_layer`。激光层订阅各机原始扫描、执行标记和射线清除，并以 `combination_method: 1` 最大代价合并；因此另一台机器人虽不进入 SLAM 静态地图，仍参与全局规划，激光清除也不会擦除静态层的墙体。之前仅配置但未加载全局激光层，会导致全局路径忽略另一台、到近处才由局部控制器阻止接近。

专项图形会话 `20261107-024000-585-cooperative-truth-test`：1036 个过滤回波位置在 SLAM 图中占据命中为 0、在全局实时障碍图中占据命中为 1036；36 个静态墙体格全部保留。该项验证两种障碍源的合成，不代表完整探索运动验收。

## 导航与协作

- 每机一套 Nav2、速度链和导航仲裁；话题、动作、服务、节点名隔离，共享 /map 和 /clock。
- 两机均沿用现有逐点到位策略、Shim 和恢复，协调器只分配任务和检查共同完成条件，不直接发布 cmd_vel。
- 本机原始激光将另一台机器人作为动态障碍；两机并发导航仍可能在窄通道互相阻挡，目前没有通道预约或联合路径调度。
- C1 停车位依据目标位置、法线、地图净空、完整车身和第二台车接近路径生成，不能只将同一个目标点发给两台车。
- C1 未定位时复用搜寻模块；共享目标清单，记录坐标系、时间和来源。仿真真值仅用于诊断和验收，不用于运行时定位或派发目标。
- 某机导航失败先保留另一机的有效状态，有界重试/换停车位；任一定位失效则暂停共同成功计时。

## 原型入口与参数

```powershell
.\Start-Autonomous-Exploration.ps1
```

正常中期启动默认双机流程。单机对照使用 `-SingleRobot`，运动/手动导航测试自动保持单机。Linux 正常中期入口同样默认双机，设置 `EDGEAI_COOPERATIVE_RESCUE=false` 可关闭。

参数集中在 `src/edgeai_navigation/config/cooperative_rescue.yaml`。`initial_relative_pose` 为估计的初始相对 SE(2) 位姿，默认 `[0,-0.60,0]`（两机朝北，robot2 在 robot1 右侧），不读取仿真坐标。AMCL 初始不确定度、收敛门槛、激光匹配率、导航重试和共同停留时间均在该文件。

定位质量检查包括新鲜 AMCL 位姿、协方差、激光端点与共享地图匹配率和持续稳定；静止时请求 AMCL 更新，必要时尝试带碰撞检查的小幅旋转。协作阶段话题 `/cooperative_rescue/state`，日志 `cooperative.log`，最终结果 `cooperative-result.json`；保存 `cooperative-map.*`、`cooperative-targets.json`、第二台运行配置及 `cooperative-nav.log`。每机仍有独立导航仲裁日志。

失败/超时/接管时停止共同成功判定，取消自有动作并请求停车。两机到圈内后还要求低速停车；完整任务总预算从 S1 成功后开始计算。

协作开始及到达后读取实时 `targets.json`。交接时的 map 坐标作为固定地图目标基准；仅当 `last_observed_ns` 晚于交接快照时刻且晚于上次接受的观测时，才接受已确认的新视觉位置。注册表 `stamp_ns` 更新不代表重新观测，不能将 AMCL 修正后旧 odom 观测的重新投影用于移动固定地图目标。检查期间最多每0.5秒墙钟刷新；接受的目标明显更新时重置连续计时。真值专项测试使用给定固定目标，不替换为感知估计。目标无效时暂停成功判定。

两机任一超出0.7m时，按当前目标重选双停车位并分别检查全局可达性，再并发接近；`rescue_repair_rounds` 默认最多3轮，每次导航仍有独立重试上限。停车余量默认0.15m，覆盖0.10m导航容差。共同停留仍须满足连续10秒仿真时间，不要求额外朝向角度。`JOINT_STATUS` 显示距离、半径、各机是否入圈、共同计时及无效原因，修正另记 `RESCUE_REPAIR`。
