# 任务层多机器人协调

顶层 `mission_coordinator` 选择任务并检查阶段门槛。每个任务的 Action 服务运行任务行为树；任务层协调节点掌握双方状态，编排分配、并行执行和失败处理。独立探索器只提供候选，Nav2 执行路径规划、控制和单车恢复。

探索任务当前实现位于 `src/edgeai_mission/edgeai_tasks/exploration.py`，节点名为 `fleet_exploration_coordinator`，任务树为 `src/edgeai_mission/config/tasks/explore.xml`。参数在 `src/edgeai_mission/config/exploration.yaml`。单机与双机使用同一套任务树和分配逻辑；单机的活动机器人列表仅包含 `robot1`。

探索候选按公共 `map` 坐标合并为共享池，过滤过期/无效来源并按端点坐标去重，
不归属于提供它的机器人。任意持有控制权、位姿有效且导航槽空闲的车都可领取，
再由接收车自己的Nav2规划、碰撞检查和恢复；来源车的代价检查不等于接收车可达证明。
目标间距仍由 `reservation_radius_m` 保证，失败历史与冷却仍按机器人分别保留。
一车断流时仍可使用另一车的新鲜非空候选；只有双方来源新鲜且都为空，才进入探索完成确认。
状态中的 `candidate_count` 是共享池数量，`frontier_source_counts` 是每个探索器原始数量，
`null` 表示来源不可用。

## 共用分配规则与 S1

搜寻任务的 `config/search.yaml` 单独设置并行目标间距 `reservation_radius_m: 0.40`，
失败历史匹配半径 `history_match_radius_m: 0.10`。
疑似目标已完成观察位的去重间距在 `midterm_single_rescue.yaml` 的
`search_suspects.min_view_spacing_m: 0.10`；已观察位置不再套用并行目标间距。
候选枚举和过滤不消耗实际观察次数，只有派发的候选才计数；疑似观察预算仍为每车所有疑似目标合计最多 6 个位置。
并行目标间距不替代 Nav2 的实际车身碰撞检查，探索和救援分配的间距不受此项修改影响。

探索、搜寻和普通目标救援共用 `edgeai_tasks/fleet_assignment.py` 的资格判断、预留和失败重试规则。
探索和搜寻按候选位置记录失败，普通目标救援按机器人与目标 ID 记录失败。
分配逻辑由任务执行器调用。任务执行器持有导航动作、取消终态和预留，并通过 ROS 发布状态与事件。

普通目标救援从本轮目标清单和定位结果生成停车候选，检查完整车身、padding、其他车辆的当前位置和已预留停车位。
分配时先最大化同时出发的车辆数，再用接近距离估计最长行程，最后比较总距离。
实际路径由各自的 Nav2 规划。单个目标最多分给一台车，单车或单目标走同一流程。

`config/tasks/s1.xml` 先取得控制权，再核对目标，然后循环派发与检查。每台车独立导航、修正和计时。
失败或超时后等待动作终态，再放开该车和目标供重新分配。目标坐标更新导致的取消不计入失败预算。
无法分配或两车重试耗尽的目标记为跳过。集成任务完成这一阶段后仍可交接 C1。
救援重试和墙钟超时在 `config/single_rescue_assignment.yaml`，到位、修正与停留要求在导航包的救援配置中。

选地图时，启动器读取 `src/edgeai_simulation/config/targets*.yaml`。其中 `targets` 定义 ID 和类型，数量从本轮选用的清单计算。
`rescue_rules.normal` 和 `rescue_rules.cooperative` 覆盖导航包的救援默认值。
普通目标有 `target_radius_m` 时按标记中心判定，否则按偏移后的停车点和 `position_tolerance_m` 判定。
`competition` 开发地图采用 0.80 m 的标记中心救援区，0.70 m 偏移用于生成导航停车点。
协作目标的 `radius_m` 以标记为中心。两类目标分别配置 `dwell_s`，仿真地面标圈和真值核验使用相同的距离基准。
目标的 Gazebo 世界坐标用于生成场景和真值，任务仍使用实时定位得到的地图坐标。

`/single_rescue/fleet_status` 和 `/single_rescue/task_state` 提供任务状态和分配事件。
`s1-assignment-result.json` 保存分配和失败历史，`rescue-target-<ID>.json` 保存逐目标真值核验，
`rescue-result.json` 汇总完成和跳过的目标。

```text
取得双方任务控制权
循环：
  汇总导航结果、超时及控制权状态
  检查探索器更新，持续失效的旧前沿先取消、确认终态再分配
  检查让路结果
  诊断失败是否与空闲车阻挡有关
  必要时选择让路位置并派发
  给其余空闲车分配不同的前沿
  检查双方候选是否持续为空且所有动作均结束
确认动作终止，保存任务结果，释放控制权
```

状态包括控制权序号、导航阶段、当前位姿、活动目标、请求/取消是否待确认、候选新鲜度、失败历史和让路状态。`/exploration/fleet_status` 每秒发布双方快照，`/exploration/task_state` 发布事件，`fleet-exploration.log` 保留原始事件；统一终端显示双方分配、到达和失败原因。任务结束记录 `exploration-result.json`。

## 失败处理职责

探索任务树的 `refresh_frontier_goals` 接收独立探索器的候选更新。活动目标附近
`frontier_match_radius_m` 内任一来源仍有候选则继续；双方来源均新鲜、连续多个共享快照不再包含该区域，
且经过 `frontier_update_hold_s` 和下发后的 `frontier_min_navigation_s` 墙钟时间，
才取消旧导航。候选短暂漂移、数据不可用或过期不会触发换点。旧动作结果确认后，
还需控制权状态为 IDLE，再按最新候选重新分配；有效空列表可以终止过期导航，
但不会凭单次空列表结束探索。正常换点不增加失败次数或触发让路。
此检查仅加入探索任务树，不取消搜寻、让路或救援动作。

| 情况 | 处理者及动作 | 结束条件 |
| --- | --- | --- |
| 单车局部停滞、占据、控制失败 | 单车 Nav2 树执行恢复 | 导航返回明确终态，或任务取消并确认终止 |
| 到点导航超时 | 任务协调器取消，等待终态，记录本次失败 | 不允许未知状态的执行槽接收新目标 |
| 导航失败且空闲车阻挡 | 导航恢复树调用共享退让能力，完成后重规划 | 让路成功/失败均有结果，受次数及任务总预算限制 |
| 前沿反复失败 | 保留按机器人分开的失败记录，换候选，有限冷却重试 | 重试耗尽报告失败，不伪装成探索完成 |
| 到达同一前沿仍无地图变化 | 等待地图刷新，限制重复到达次数 | 存在候选时不得报告完成 |
| 救援停车点不可达、目标更新 | 既有 S1/C1 任务树重新选点或修正 | 按救援距离、朝向、停车和停留条件检查 |
| 控制权被人工接管、状态失联 | 停止任务并清理自己持有的动作 | 不覆盖操作员的新控制命令 |

## 阻挡诊断和让路

`edgeai_nav/yield_routes.py` 在公共地图的只读副本模型上对比两次连通性：保守车身包络下的静态通路，以及添加对方车身后的通路。前者可通、后者不通，记录 `peer_blocks_static_route`。静态图本身不通、搜索预算耗尽或数据缺失均为不确定，不归责于对方。

这项证据只描述当前静态模型。其他激光、深度和膨胀代价仍可能影响实际规划；并未实现完整 Nav2 代价层的反事实原生规划。诊断不会清除真实代价地图、关闭碰撞检查或使用仿真真值。

仅当对方在同一任务控制权下、状态新鲜、导航槽为空且为 IDLE 时允许让路。选择距原位置较远、远离请求方和受阻路线、已知净空且可达的位置。执行仍通过原有导航 Action，保留全部障碍层及单车恢复。让路导航失败或超时也消耗有限尝试，不无限往复。

联合探索、目标搜寻和 S1 的任务树只分配导航目标、处理终态和重试，不再排列退让步骤。
导航恢复树先请求共享 `peer_yield_server.py`；无法确认阻挡或退让失败时继续原有单车恢复。
请求方可仍处于 ACTIVE，但必须已停止；对方必须是 MANUAL、IDLE、状态与里程计新鲜且静止。
退让通过 `navigation/yield_to_pose` 进入位置到达导航，原生规划和执行保留实时对方车身层。
该入口只接受空闲槽，且普通新目标不能替换正在执行的退让。

C1 预规划尚未进入导航树，因此 `tasks/c1.xml` 显式调用 `yield_peer`。
它通过 `/navigation/yield_peer` 或 `/robot2/navigation/yield_peer` 请求同一导航能力。
Action沿用 NavigateToPose 消息：输入位姿仅表示请求方受阻路线的终点，成功表示同伴已移动并释放该路线；
它不选择C1救援停车点，也不代表请求方已到达目标。
起点占据仍先尝试原有短距恢复；失败时也可诊断实际空闲同伴是否阻挡。
候选停车点的假想同伴冲突不会直接授权退让。

退让成功必须测得至少5厘米移动，并在静态诊断模型中确认原通路已释放。
随后C1清除旧停车锁定和停留计时，独立重新选择两车停车点并验证路径。
无确定阻挡则普通重试；取消需确认对方导航终态；通信终态不明返回fatal，C1不得继续派发。
双方请求串行处理；退让车自己的恢复树不能递归请求另一轮退让。
共用参数位于 `edgeai_navigation/config/peer_yield.yaml`，任务分配配置不再保留另一份退让参数。
尝试次数按两车控制权阶段累计，移交控制权后重置。

## 验证范围

2026-11-11，真实ROS任务执行器、行为树和任务协调器接入模拟导航Action/控制权服务，验证“阻挡→空闲车让路→原车重试完成”及“让路被拒绝→有限失败退出”，两项通过。另有静态走廊、封路、不确定诊断和失败历史检查。

Gazebo/RViz 联合探索实测 `joint-yield-validation-20261111`：两车同时分配和移动，共9次分配、4次导航失败后继续选择，最终保存23.41 m²地图并正常退出。该场景没有自然触发空闲车让路，不能替代实际动态会车验证。完整搜寻、S1/C1和回环精度仍需另行核验。WSL图形启动默认采用 `xcb_glx`，保留用户显式设置；本轮仍出现过偶发上下文创建失败，重启独立会话后恢复，不视为图形问题已根治。

2026-11-12退让职责迁移：10项单位测试、5项真实ROS动作测试、3项C1任务树定向测试、2项双车任务/导航退让测试及控制权接单保护测试通过；两个命名空间生成的导航树接口检查通过。实际安装目录中的服务入口已在隔离域启动并验证两个Action可发现。本轮未运行或干预Gazebo仿真。

## 原生命名空间

机器人数据、导航 action 和控制权服务分别位于 `/robot1`、`/robot2`。公共地图 `/map`、TF话题、目标登记 `/targets` 和任务调度接口保持共享。已删除机器人1到根话题的图像、雷达、里程计和速度转发，以及旧TF帧别名。

Nav2生命周期管理器与各自机器人处于相同命名空间。定位时公共地图管理器只管理 `map_server`；每车的 `localization_manager` 只管理本地 `amcl`，避免跨命名空间bond连接错误。

`Start-Autonomous-Mission.ps1 -SingleRobot` 运行单机特例；默认入口运行双机。建图、搜寻和S1分配按活动机器人列表运行，C1仍要求两台。单机与双机继承相同DDS participant容量设置。

旧AUTO探索导航入口和观察暂停/恢复服务已移除。权限节点仅提供MANUAL（任务/手动接管）和STOPPED；探索器只生成候选。状态中的 `explorer_paused=true` 表示探索器不直接派发导航，不代表停止候选计算。运动测试保留。
