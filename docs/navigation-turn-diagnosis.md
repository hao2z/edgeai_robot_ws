# 后方目标掉头失败：探索器、规划器和控制器配合诊断

2026-10-28，在`codex/Junnan-dev`的实际图形仿真中观测并记录。

## 已确认的现象

180秒墙钟预算的建图测试`20261028-214010-679-domain86`退出码0，
观测覆盖率81.65%，没有完成全区域探索。约模拟时间50秒之后，目标切到
车身后方，机器人在约(2.548, 1.007) m附近往复摆动。

只读快照窗口58.35–85.25模拟秒内，位置首尾差约2.7e-10 m，朝向范围
仅约12.17°。这说明机器人没有完成掉头，也没有继续沿路线移动。
这些数值是该仿真记录，不是实机精度或重复性结果。

全局路径开头确实包含同一位置的一串转向姿态，例如-0.464、-0.571、
-0.678、-0.785 rad。局部轨迹却多次只选择小幅反向调整。
全局姿态在map、局部轨迹在odom，不能直接相减绝对yaw；这里比较的是
各自轨迹内部的转向增量方向。

最后一份快照中，全局/局部原始代价地图的轮廓边界采样最大代价分别为
232/226，没有采到致命格254或未知格255。该检查只证明此时这些边界
采样未撞上致命格，不是物理碰撞证明，也没有证明全部未来旋转姿态安全。
本轮主要异常不是上一轮的`Start occupied`。

## 配合问题

1. Lattice已给出转向路径，但DWB偏重位置/路径代价，没有在这组参数下
   稳定执行大角度换向。仅有全局可行路线，不代表局部控制必然跟踪成功。
2. 探索器约每3秒取消并重新发送相同坐标目标。上游可见收益抢占分支在
   收益不足时可先取消、下次地图回调再选目标；结果可能仍选回原目标。
   取消/重发会重启导航执行，妨碍连续掉头，也干扰无进展检测。
3. 原探索器“足够接近”阈值0.20 m，比Nav2的0.15 m位置容差宽。
   两者是不同完成语义，不能将探索器取消等同于Nav2成功到点。

## 修正

- 默认矩形profile使用Nav2 Rotation Shim包裹DWB：新路径方向差超过
  0.785 rad时先原地对齐，差小于0.25 rad再交回DWB。
- 使用Lattice路径自带朝向，闭环读取里程计；角速度0.5 rad/s、角加速度
  0.8 rad/s²，保持既有矩形轮廓和旋转预测碰撞检查。
- 禁用普通“可见收益”抢占，保留目标被阻挡时换目标及近目标完成机制。
  可见收益抢占若未来重新启用，间隔预设12秒；并未声称这等同于真正的目标去重。
- 探索器近目标阈值统一为0.15 m。探索收益变化不再不断打断正常执行。

## 独立后方目标检查

命令：

```powershell
powershell -ExecutionPolicy Bypass -File .\Start-Autonomous-Exploration.ps1 -TurnTest -Duration 90
```

该模式不启动探索器，在初始轮轴位置后方0.60 m处发送单个Nav2目标，
目标朝向相反。它用于隔离掉头控制，不代表探索覆盖率测试。

`20261028-214851-036-domain86-turn`实际结果：

- Nav2返回成功；从首条到末条轨迹约9.47模拟秒。
- 累计转动约183.24°，最终朝向误差约3.24°。
- 位置误差0.148 m，符合当前0.15 m探索到点容差，不是5 cm停车精度。
- 最大发送角速度0.5 rad/s，未绕过轮廓碰撞检查。

这是开阔初始位置的一次定向验证，不能替代原故障点及完整探索的验证。
后续集成测试还需检查阻塞恢复、转向中目标稳定性和未观测房间覆盖。

## 修正后的集成短测

`20261028-215153-441-domain86`使用90秒墙钟预算，退出码0，观测覆盖率
73.72%，未完成全场。该预算与前述180秒测试不同，不能据此比较算法优劣。
正常执行不再持续出现约3秒一次的收益型取消；机器人能够继续运动，并在
约21:53:01成功到达新目标。但是仍记录到`Start occupied`（错误码205）和
`No valid trajectories out of 419`，之后才再次到达目标。

所以本次只能确认后方目标掉头的单项检查通过、正常目标执行更连续，不能
宣称探索器、全局规划和局部控制的全部配合问题已解决。当前仍需处理：

- 当前起点已被判占用时，避免将同一失败目标或其他目标高速循环下发。
- 核对同一现场的全局/局部栅格、连续姿态与Lattice离散朝向碰撞判断。
- 区分收益型抢占、目标被阻挡的撤销、导航失败重试和正常到达；不能都按
  “重复目标”归为同一原因，也不能把正常退出码当成任务完成。
