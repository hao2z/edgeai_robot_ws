# 探索与 Nav2 恢复协调

Nav2 持有已接受的 NavigateToPose 任务，负责重规划、进展判断和原生行为树恢复。
探索器只在任务返回最终成功或失败后重选目标；用户停止、测试时限及系统退出仍可中断。

2026-10-29：2.5 cm 地图下，最小前沿为 10 格、决策地图膨胀半径为 2 格，
恢复到原先 5 cm 网格中 5 格/1 格的大致物理尺度。启用终态后的 1.5 秒
仿真时间等待，给地图更新留出时间；它不保证地图已收敛，也不以等待代替建图。
固定上游适配新增 START_OCCUPIED(205) 处理：暂停探索，不抑制当前前沿，
不继续派发其他候选；仲裁节点同步为 STOPPED。检查起点定位、地图及碰撞
轮廓后，可通过 RViz“自动探索”恢复。该处理限制失败传播，不证明已消除起点占据。

- `movement_time_allowance: 15.0`：按仿真时间检查无进展，矩形配置所需位移仍为 0.10 m。
  这是进展检查阈值，不能保证所有失败都恰好在 15 秒触发恢复；规划失败也可更早进入恢复。
- `goal_preemption_enabled: false`：不以新前沿替换活动任务。
- `goal_preemption_complete_if_within_m: 0.0`：关闭探索器接近目标时主动取消的捷径。
- `goal_skip_on_blocked_goal: false`：代价地图更新不取消活动任务。
  此上游开关也控制派发前目标点检查，关闭后该检查同样停用；仍保留前沿搜索的代价地图处理，
  Nav2 继续负责完整足迹的规划、控制和恢复碰撞检查。
- `frontier_suppression_no_progress_timeout_s: 0.0`：禁用外层距离进展计时，避免旋转、等待、倒退被探索器打断。
  最终失败的前沿仍使用已有的失败抑制与候选重选功能，抑制时间 90 秒。

上游 1.6.1 把外层超时最小限制为 0.1 秒，因此不能只改 YAML。
`src/edgeai_exploration/tools/prepare_frontier_runtime.py` 在独立生成目录对固定版本应用最小适配：

## 统一控制权与恢复证据（2026-10-28）

新增 `src/edgeai_navigation/scripts/navigation_authority.py` 和独立可测试的 `authority_policy.py`。
探索器、RViz 与 Nav2 通过同一仲裁节点交接任务。这里的权限是协作节点的控制权规则，
并非 DDS/SROS2 身份认证；直接访问内部端点或向底盘速度话题发布仍属于管理范围之外。

| 入口 | 权限与作用 |
| --- | --- |
| `/exploration/navigate_to_pose` | 仅 AUTO 模式可申请 |
| `/navigate_to_pose`、`/goal_pose` | 仅 MANUAL 模式可申请；活动任务结束前拒绝新目标 |
| `/navigation_authority/set_manual`，SetBool | true 请求手动接管，false 请求自动探索 |
| `/navigation_authority/stop`，Trigger | 停止探索调度并取消导航；响应表示请求已登记 |
| `/control_exploration`，ControlExploration | 兼容立即 start/stop；延迟与退出节点请求明确拒绝 |
| `/navigation_authority/state` | 实际模式、任务所有者、状态、目标 UUID、故障和恢复证据 |
| `/navigation_backend/*` | Nav2 内部动作；由受管理的 launch 统一重映射 |

RViz 面板提供自动探索、手动接管、停止任务三个按钮。手动接管后应等待状态变为空闲，再设置目标。
请求中指定其他恢复行为树会被拒绝，避免普通客户端替换统一策略。

状态转换：IDLE → SENDING → ACTIVE → 最终结果 → IDLE。
显式停止进入 CANCELING，取消确认不释放任务。接单超过 10 秒、取消后超过 5 秒未收到终态，
或仿真仍前进而反馈超过 10 秒未到，进入 UNKNOWN，保留执行槽，禁止重复派发。
当前任务的迟到接单、反馈或终态可按对应规则消除不确定性，过期任务回调不能释放新任务。
通信握手期限使用单调墙钟；运动进展使用仿真时间；暂停仿真不会触发反馈失联判断。
无法核实旧任务终态时不会强制释放；需要先核实/停止后端，再通过完整受管理会话重启处理。

接管或停止时先暂停上游探索调度，由探索器发起取消。服务失效或取消未传播时，
仲裁器最多等待 1 秒后直接向 Nav2 请求取消，仍等待终态才能交接。
原生服务移动到 `/exploration/control_exploration`；受管理的运行入口负责此重映射。

原生 Nav2 行为树保留 1 Hz 重规划、6 次外层恢复重试和局部失败清图。
系统恢复轮换为清图与短暂等待、尝试安全位移、环境等待。
位移分支依次尝试后退 0.08 m / 0.04 m/s、前进 0.06 m / 0.04 m/s、旋转 0.50 rad。
使用 Nav2 自身的 BackUp、DriveOnHeading、Spin，保留矩形足迹与所有碰撞检查。
这些动作不保证在任何困境中成功；若没有安全运动空间，应明确失败而非绕过检查。

恢复结果分三层：动作的最终状态；新鲜里程计是否证明平移至少 0.04 m 或旋转至少 0.25 rad；
同一目标是否重新跟踪路径、移动至少 0.05 m 且距离减少 0.10 m，或最终到达目标。
只有全部满足，才报告 NAVIGATION_RESTORED。清图、等待和动作接单不能单独证明脱困。
位移使用消息自身时间戳，过期数据和参考系变化不能作为位移证明。
里程计证据不是独立地面真值，实机仍需结合定位质量与打滑检测评估。

每次交接、取消、恢复及终态写入会话的 `authority.log` 和 `authority-events.jsonl`，
包含单调时间、仿真时间、任务编号及动作证据；统一事件流同时写入 `events.log`。
RViz 显示控制权、任务状态和恢复结果，启动时另打开绑定本轮日志的 Windows 终端。

验证：10 项状态/证据单测和真实 ROS action 握手测试通过。ROS 测试涵盖手动越权拒绝、
暂停探索后取消、取消确认后仍禁止交接、超时 UNKNOWN 阻止重复目标、迟到终态释放以及里程计时效。

GUI 故障注入结果在 `tests/results/runs/20261028-234650-662-domain86-recovery/recovery-result.json`：
临时提高进展要求以触发实际 Nav2 恢复，恢复开始后还原参数，测得后退约 0.083 m，
同一 Action UUID 保持，原目标最终成功，`success=true`。测试使用生产恢复树，不是假动作服务器。
正常探索 60 秒测试 `20261028-234853-046-domain86`：5 个目标成功，正常时间限制结束；
停止时发现探索器额外申请目标的竞态，已据此调整先暂停调度再取消的顺序。

## 策略层集中与 ROS 边界（2026-10-29）

前期 Mileston 会话的审查指出，控制规则曾分散在 `authority_policy.py`、
ROS 回调、探索器控制服务和 Shell 清理路径中。当前已将控制端点、接单/取消/反馈期限、
探索器取消宽限期和任务模式规则集中到 `AuthorityConfig` 与 `Authority`。
`navigation_authority.py` 只负责把外部事件转换为策略事件，再执行策略产生的 ROS 动作。

重复的相同模式请求现在是幂等操作，不会刷新取消宽限期。探索器控制 RPC 增加了请求代次和
5 秒响应期限；迟到响应不会改写新的模式状态。探索器以 `autostart=true` 启动时，AUTO 初始状态
直接视为已同步，避免每轮启动再发送一次无意义的 start RPC。只有自动探索与手动/停止之间发生
真实交接时，才调用一次暂停或恢复服务。

这一层仍然是协作式控制策略，不是 DDS 身份认证；ROS 仍保留在必须的边界：地图、里程计、
Nav2 Action 和底盘速度保护。进一步移除探索器与仲裁器之间的 ROS Action/Service，需要把
固定版本 `frontier_exploration_ros2` 的 Core 直接作为同一进程组件接入，并为其 Nav2 适配器、
生命周期和测试提供稳定 ABI；在完成这项隔离前，不把未经验证的半成品嵌入层放进运行入口。

本轮新增策略单测 2 项，现有策略单测共 12 项，日志单测 5 项，均通过。

## 2026-10-29 同一控制方目标抢占修复

此前探索器直接发送替代目标时，仲裁器因旧目标 ACTIVE 而拒绝请求，
探索器继而抑制候选。这是任务接口不兼容，不是目标不可达。
现在同一控制方可接受一个待交接目标，主动请求取消旧任务；仅收到取消确认
不会释放槽位，收到旧任务终态后才派发替代目标。旧任务自然成功也走同一交接。
待交接目标可取消，控制模式切换会撤销待交接目标；UNKNOWN 状态仍不接收
新目标。排队槽位为一个，不用于并发执行或无限缓存。

验证：run-authority-tests.sh 的 12 项策略测试与 2 项真实 ROS Action 测试通过。
新增测试复现活动 AUTO 任务期间直接发送新目标，验证接受、旧任务取消、
终态前不派发、终态后恰好派发一次，以及取消排队目标后不会派发。
未启动仿真；现有进程需要重启后才加载修复。
