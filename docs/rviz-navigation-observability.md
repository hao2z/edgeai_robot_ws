# RViz中的轮廓、地图与时间对齐

默认视图与日志已精简，当前入口行为见 [日常观察与诊断输出](observation-output.md)。
下表包含可选诊断显示；全局代价地图、全局轮廓和深度图不再默认显示。

`Start-Autonomous-Exploration.ps1` 自动加载这些显示，并启动只读诊断节点。
所有活动节点使用Gazebo `/clock`。诊断节点不发布速度、位姿估计或TF，不参与控制。

| 显示 | 含义 |
|---|---|
| 灰色 SLAM map | 已建占用地图，墙体和未知区域 |
| Global navigation costs | 全局规划实际使用的代价地图，含SLAM静态层、雷达障碍和膨胀 |
| Local live obstacle costs | 局部控制实际使用的滚动代价地图，雷达障碍和膨胀 |
| 绿色路径 | Nav2 `/plan`，全局规划路线 |
| 绿色方块 | 开源探索器候选观察点，不是障碍物 |
| 粉色轨迹 | DWB `/local_plan`，当前选中的短时局部轨迹 |
| 红色散点 | 当前雷达扫描的命中点 |
| 青色粗虚线轮廓 | 全局代价地图发布的轮廓，重新投影到统一对比时刻 |
| 黄色细实线轮廓 | 局部代价地图发布的轮廓，重新投影到同一时刻；通常与青色重合 |
| 品红箭头 | 固定初始map→odom关系后所得里程计投影，与当前SLAM修正位姿的差值 |
| Exploration frontiers | 开源探索器发布的候选前沿标记 |

**任何轮廓线的颜色都不是碰撞检查通过或失败的判定。** 这些线显示碰撞模型
的位置和形状；代价地图才显示它周围的障碍/膨胀信息。原来的固定绿色矩形
已由上述有图例的显示代替。不要把不同位置的线当成独立传感器定位结果。

左侧显示列表可分别开关全局/局部代价地图，避免重叠颜色影响判断；红/紫色
代价区域既可能包含实体障碍，也可能包含安全膨胀，不能统一理解为物理墙体。
`Raw global/local footprint (message time)` 默认关闭，供需要时对照原始消息；
`Navigation TF` 默认关闭，可查看map、odom和base_footprint的坐标轴。

品红箭头反映SLAM相对固定里程计锚点的修正，不是真值误差，也不是第三套定位。
默认RobotModel仍使用RViz当前TF；对齐轮廓使用约100 ms前的公共时刻，两者在
移动中可能有可解释的小偏移。0.20 m/s下100 ms对应约2 cm，不能误认为尺寸变化。

## 时间对齐的做法和边界

1. 导航参考点统一为轮轴地面投影 `base_footprint`；运动位姿链是
   `map → odom → base_footprint → base_link`。
2. SLAM发布地图间隔改为0.5 s；全局/局部代价地图均20 Hz计算、10 Hz发布。
   两者都使用传感器消息时间和TF，保留全局map/局部odom各自的用途。
3. 对比节点选取模拟时间 `now - 0.10 s`，使用TF2查询该精确时刻的变换。
   各原始轮廓先按自己的消息时刻变回base_footprint，再投影到公共时刻。
   找不到历史TF时显示等待，不回退到latest，也不把旧消息改成新时间戳。
4. RViz右侧独立面板显示中文图例、map、global/local costmap、scan、odom及两种轮廓的消息年龄。
   默认地图超过2.5 s、其余超过0.6 s、未来时间超过0.2 s或时间戳为零时告警。
   这些是开发诊断阈值，不是独立安全停车机制。

`TIME CHECK OK` 只表示本次诊断所需数据时效和指定时刻TF检查通过，**不代表
道路可通行、无碰撞或所有算法计算严格同时完成**。各节点仍独立调度；地图内容、
传感器可见范围、全局离散朝向与局部连续姿态仍可能产生差异。同步频率也不能
消除定位误差、SLAM修正、地图离散误差或打滑。

每次运行额外保留 `alignment.log` 和 `alignment.jsonl`，记录比较时间、各消息
年龄、缺失/过期项、TF失败及修正量。该记录使用模拟时间，便于与原始导航日志对应。
图例采用真正的RViz停靠面板，文字不再绘制到地图上。WSL可使用本机已安装的
微软雅黑字体显示中文，不复制或分发该字体；普通Linux使用系统字体。
面板失去诊断消息后也会按墙钟提示停止更新，避免模拟时钟停止时显示假实时状态。

## 频率与性能

RViz目标帧率60 FPS，雷达20 Hz，相机30 Hz，里程计50 Hz，IMU100 Hz。
物理步长仍是1 ms，仿真目标倍率仍是1.0，没有加速模拟时钟。控制器保持20 Hz；
可视化、传感器、物理和控制频率各有含义，不因提高画面帧率就改写物理模型。
诊断面板显示按模拟时间统计的实际接收Hz，以及模拟时间/墙钟时间的倍率。
设置值不等于实际达到值，只有数据年龄和实收频率一起正常，才能判断更新及时。

侧栏插件源码在 `src/edgeai_navigation_rviz`。更新后运行
`bash scripts/setup/build-workspace.sh` 构建，正常启动入口会加载它。

相关实现：`scripts/ros/navigation_diagnostics.py`、
`src/edgeai_exploration/tools/prepare_rviz_diagnostics.py`。运行前只需正常构建/准备流程；
这些诊断脚本直接来自当前仓库。旧MarkerArray显示的`Marker Topic`字段已修正为
当前RViz使用的`Topic`字段，使诊断图例和原有前沿标记能真正订阅到数据。
