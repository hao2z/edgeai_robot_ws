# 日常观察与诊断输出

自主探索默认只打开一个事件终端、Gazebo 和 RViz。额外 ROS shell 和
`Open-ROS-Monitor.ps1` 保留为手动工具，避免多个窗口重复显示同一批消息。

## RViz 默认视图

保留地图、机器人、雷达、局部代价地图、全局路径、局部轨迹、探索候选点、
局部车身轮廓及 RGB 相机。全局代价地图、原始轮廓与 TF 可在 Displays 中开启。
默认不创建深度图和点云显示；需要时用 Add 添加 Image `/camera/depth_image`
或 PointCloud2 `/camera/points`。有些 RViz Image 插件即使配置为禁用也会打开面板，
所以从默认配置中移除，而不是只把 Enabled 设为 false。

右侧先显示时间健康状态、估计速度、仿真倍率、数据年龄和实收频率。
勾选“显示图例与说明”查看颜色含义。全局对齐轮廓可用 ROS 参数
`/edgeai_navigation_diagnostics show_global_outline=true` 开启。
时间检查通过不代表导航成功、无碰撞或厘米级精度。

## 事件终端

- 青色：阶段和目标坐标变更；绿色：到达、时间健康恢复。
- 黄色：同目标重发、无进展、恢复或数据过期；红色：错误、进程异常。
- 同类重复事件每15秒汇总一次并累计计数，结束时刷新剩余计数。
- 以探索器 dispatch 坐标区分目标变更与重发；不把导航端的接收记录再报一次。
  坐标按厘米取整，只用于观察输出，不影响实际下发的导航目标。
- 充电桩未配置仅作简短说明；Nav2 自动选用唯一 goal/progress checker 的提示
  不进入事件流。其他未分类 WARN/ERROR 仍进入摘要。
- 成功截图只写入原始记录，截图失败进入警告。
- 颜色仅用于终端，日志文件不含颜色控制码。设置 `NO_COLOR=1` 可关闭颜色。

## 保存文件

`events.log` 是可读事件，`events.jsonl` 保存严重级别、原始证据和计数。
`log-summary.json` 汇总目标变更、重发与重复事件计数；这些计数不是覆盖率或成功率。
`console.log` 合并各原生进程输出，不再叠加 `/rosout` 的同一份消息。
`nav.log`、`explore.log`、`sim.log`、`rviz.log`、`alignment.log` 和 `rosout.log`
仍完整保存。`alignment.jsonl` 保留逐秒时间诊断；地图评估在 `evaluation.log`。
重复日志不再反复显示，但仍可沿原始证据追溯，不删除历史运行结果。
