# 任务行为树重构记录

## 当前实现：独立任务Action与任务树

更新：2026-11-10。默认入口仍执行建图→S1→地图交接/定位→C1；固定规则调度，不新增任务评分。

| 层级 | 实现 | 责任 |
|---|---|---|
| 协调 | `mission_coordinator`、`config/integrated.xml` | 决定任务、发出/取消任务Action、汇总结果、总预算与进程健康检查 |
| 任务 | 同一 `task_executor` 实例化为S1/C1节点，`config/tasks/s1.xml`、`c1.xml` | 单位操作顺序、导航与任务两层重试、条件检查、修正/重选停车位 |
| 单位算法与ROS适配 | `scripts/task_units.py`，复用navigation几何、定位和停留/修正模块 | 计算候选、派发/轮询、一次条件检查；实际运动由Nav2完成 |

协调器调用 `/mission/tasks/s1/execute` 和 `/mission/tasks/c1/execute`，类型均为 `edgeai_mission/action/ExecuteTask`。Goal为任务ID；Feedback包含操作和JSON检查摘要；Result包含成功、原因、清理确认与最终测量。没有重复判断S1/C1的全局检查节点。

任务树通过 `/mission/tasks/{s1|c1}/units/{operation}` 的 `std_srvs/Trigger` 调用适配器，JSON响应描述计算/检查事实。较长的准备或算法调用可以阻塞服务适配线程，但不会阻塞C++树线程；取消任务Action时终止并回收适配进程。服务本身不能单独取消，不作为通用分布式单位行为协议。

S1树：接管→选目标/必要搜寻→选接近点→导航→独立检查→必要旋转/短进修正→连续停留→记录。C1树：地图交接→定位→选双位→派发两机导航→分别轮询→共同条件/停留检查→必要重选→记录。

2026-11-10启动时序修复：C1地图交接之后，树显式执行`wait_navigation_ready`→`localize`，该准备序列使用导航尝试上限进行有界重试，失败不会重复保存地图或停止SLAM。就绪检查查询共享地图与两机AMCL、规划、控制、行为服务器、速度平滑器、碰撞监视器、导航器的真实生命周期状态，全部active才允许进入定位辅助运动；发现Action端点或仲裁IDLE不再视为就绪。45秒单次就绪等待及各次定位仍受原任务总预算限制，取消和控制权丢失不重试。

会话`20261110-012827-585-domain86`：S1成功，C1在行为服务器尚未激活时发送Spin而被拒；日志显示拒绝发生在墙钟1794270885.6758，Spin于1794270887.1272才激活。该轮未进入停车位导航，不能归因于C1目标或双机停车冲突。任务适配进程的SIGTERM改为设置停止标志，在Python循环边界退出，避免信号处理器在任意rclpy扩展调用/析构内抛异常。完整仿真复测由用户执行。

两机各保留Action handle和result future；一机先到或失败，不会重发另一机仍在执行/已到达的导航。换位优先锁定健康机器人的既有停车位；没有可行组合时，树上有显式“取消全部→重新选双位”分支。

### 恢复与重试边界

- Nav2规划/控制失败、无进展、起点占据恢复仍在共享 `explore_recovery.xml`，各到位策略保留入口。任务层在Action仍执行且未超时时只轮询，不抢先恢复。
- 候选计算和 `ComputePathToPose` 不运动。C1预检查遇START_OCCUPIED不阻断后续导航，由实际导航树尝试退出；其他规划失败继续筛选。
- 导航失败或明确超时后任务树才重试。取消必须等动作终态，仅取消响应不算结束。外部取消、人工接管和权限丢失不可重试。
- 导航到达不等于救援完成。S1检查实际任务距离、朝向、低速和连续时间；C1用共同新鲜采样检查两机距离、定位和停车，累计共同10仿真秒。S1圈内朝向不合格可进入独立修正。
- 次数由既有配置生成：S1 `navigation_max_retries` / `rescue_max_retries`；C1 `navigation_retries` / `rescue_repair_rounds`，值表示额外次数。`mission-runtime.json`记录包含首次的尝试上限。
- S1共享导航仿真时间预算，C1每次导航用墙钟；任务及协调器总墙钟预算不因重试重置。目标变化重建接近点不消耗普通失败次数，但受总时限限制。

每轮固化 `mission-trees/`。新增 `s1-task.log`、`c1-task.log`、`task-unit-events.jsonl`、`task-*-worker-result.json`；兼容原救援结果文件。任务服务器意外退出会终止流程，身份校验后清理遗留适配进程和自有导航进程。

### 当前迁移边界

默认流程不再调用旧脚本完整S1/C1 `execute()`；`mission_stage.py`只保留停止探索和保存地图。独立旧入口仍供专项测试。几何、感知、定位收敛和搜寻算法复用原模块；搜寻内部候选导航/扫描、建图途中观察和前沿调度尚未逐项拆成任务树子树。本次迁移范围是默认救援的任务Action与编排，不代表完整设计中的20类行为和所有比赛模式均已实现。

独立Part 2、跨主机租约、通道让行预约、强类型单位接口及完整搜寻/观察子树仍属后续工作。任务估计判定与仿真真值核验保持区分。

## 第一阶段历史记录

以下描述2026-11-09时点的过渡实现；当前职责与边界以上文为准。

2026-11-09。目标是固定规则调度，不新增任务评分。

### 已迁移

新ROS包 `edgeai_mission` 提供C++节点 `mission_coordinator` 和BehaviorTree.CPP阶段树 `config/integrated.xml`：

```text
等待探索完成事件
 → 停止观察调度，停止导航并确认探索已暂停
 → 保存地图与目标快照
 → 若启用救援：S1
 → 若启用双机且S1成功：C1
 → 记录mission结果
```

调度是固定顺序和条件门控，没有任务评分。节点从会话启动时获取初始相对参考并临时发布robot2粗略TF；C1开始前停止该发布，将参考显式交给协作适配器。原独立协作脚本的等待S1模式仍供兼容使用，新默认流程不再启动第二个“等待S1后自行决定开始”的协调器。

Shell保留配置、进程启动/清理、隔离测试驱动、截图和地图评估；已删除其中“轮询探索完成→启动S1→等待C1”的业务分支、重复观察/搜寻参数计算，以及无人使用的探索完成文件监听器。普通任务由节点订阅可靠、持久的 `/exploration_complete` 事件；旧lite后端的日志适配集中在探索树节点内。

普通/指定朝向/救援的Nav2树保留相同规划失败恢复入口；不再由 `goal_policy.py` 按rescue标签删去恢复。到位检查器、终点朝向与倒车设置仍按原策略区分，此次不修改控制参数。

### 入口和记录

常用Windows和Linux入口不变。源码新增包后执行：

```bash
bash scripts/setup/build-workspace.sh --packages-select edgeai_navigation edgeai_exploration edgeai_mission
bash edgeai.sh check
```

包的直接入口（通常由启动器准备配置并启动）：

```bash
ros2 run edgeai_mission mission_coordinator --ros-args \
  -p use_sim_time:=true -p config:=/absolute/session/mission-runtime.json
ros2 service call /mission/stop std_srvs/srv/Trigger '{}'
```

`/mission/stop`只确认收到取消请求，最终结束以 `mission-result.json` 和动作停车确认记录为准。协调器取消时终止并等待当前适配进程，再请求两机仲裁停止；无法终止的适配进程有强制关闭上限。此进程级机制不等价于后续设计的分布式执行租约。

每轮新增 `mission-runtime.json`、`mission-reference.json`、`mission-processes.json`、`mission.log`、`mission-events.jsonl`、`mission-result.json` 和 `stage-*-result.json`。任务状态发布在 `/mission/state`，主控制台转发关键阶段。适配器退出码0但无确认的成功结果仍按失败处理；S1失败不启动C1；探索时间到不当作探索成功。

### 当时保留的过渡部分

- `normal_rescue.py` 和 `cooperative_rescue.py` 的内部状态机、救援判定、搜寻和修正仍在原模块；当前树运行的是**阶段适配器**，尚未拆成20类单位行为，不是完整重构完成。
- 观察调度器在探索阶段仍作为受管子进程运行；前沿探索器仍自行选择/派发目标。后续分别迁入树，不能声称全部自动决策已统一。
- C1适配器仍采用原双机接近/判定逻辑；新节点目前掌握阶段调度和汇总结果，尚未独占所有单位行为检查。
- 本次沿用探索预算与S1/C1原有阶段预算；未把比赛13分钟总预算或独立Part 2模式默默改成新默认。
- 协调器失联后的机器人本地租约停止、强类型ExecuteBehavior接口、跨机让行预约，以及失败后保留AMCL/TF供长时间核验，仍需下一阶段实施。
- 其他候选模块的路径长度/可见性排序保留；它们不是本次删除的“任务调度打分”。

设计与异常矩阵见 [重构设计](mission-behavior-tree-design.md)。本阶段先验证固定顺序、失败传播、取消、命名空间参考交接及无冗余Shell决策，再继续拆单位行为。
