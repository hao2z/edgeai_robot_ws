# 几何约束、转弯与精度边界

2026-10-28。对照“梳理mileston前第一阶段的任务”会话、当前模型和 Rulebook V0。
本次修正运动参考点及参数一致性，不把参数容差等同于实测精度。

## 已修正的参考点和尺寸

差速里程计的运动参考点应与驱动轮轴中点一致。原来两个驱动轮的 x 坐标
相对车体中心为 +0.0875 m，`base_footprint` 却位于车体中心，导致转弯模型
与实际几何参考点不一致。现在保持车体、轮子和传感器在 `base_link` 内的
几何关系，让 `base_footprint → base_link` 的平移为 (-0.0875, 0, 0.049) m。
所有导航、SLAM 和里程计继续使用同名 `base_footprint`，但其含义变为轮轴地面投影。

| 项目 | 当前值或含义 |
|---|---|
| 上板尺寸 | 0.375 × 0.265 m，不是含脚轮/驱动轮的完整轮廓 |
| 驱动轮半径、轮距 | 0.049 m、0.300 m；仍需实机标定有效轮径与轮距 |
| 矩形轮廓坐标 | x∈[-0.3125, 0.1125]，y∈[-0.165, 0.165] m |
| 名义包络 | 0.425 × 0.330 m，覆盖脚轮全部摆动采样范围 |
| 每侧 padding | 0.010 m，为开发余量，未证明覆盖实机误差 |
| 含 padding 的包络 | 0.445 × 0.350 m |
| 保守矩形原地旋转扫掠直径 | 约 0.734 m，围绕轮轴计算 |
| SLAM、代价地图、Lattice 网格 | 默认统一 0.025 m；保留 0.05 m 对照配置 |

原来忽略 8.75 cm 偏置时，理想无打滑的 90°/180°转向，车体中心相对
错误的“保持原地”预测可偏离约 12.4/17.5 cm。修正坐标关系消除了这项
建模不一致，但没有消除编码器、打滑、外参或 SLAM 误差。

0.40 m 净宽仅是几何说明：0.35 m 宽的有效矩形正对通道时，两侧各余
2.5 cm，转斜后可能无法通过。它不是比赛门宽，也不能证明实机可靠通行。
场地约 5×5 m 来自规则草案，最终尺寸、门宽等仍以官方技术参数为准。

2026-10-29 仿真极限通行实验：默认矩形配置的全局/局部膨胀半径均为
按含 padding 的矩形外接半径向上取整至一个栅格，当前为 0.375 m。
cost_scaling_factor 为 5.0，软代价衰减更快；DWB 最小线速度
设为 -0.08 m/s，与全局倒车扩展及速度平滑器一致。保留真实矩形、1 cm
padding 和碰撞检查。这是仿真实验配置，未作为实机安全参数验证。

按 competition_rooms.sdf 的碰撞盒边界计算，左上、右上、右下门洞净宽
分别为 0.85、0.75、0.75 m。0.375 m 两侧膨胀在这些门洞中间分别留出
0.10、0、0 m 不受该两侧墙体膨胀影响的条带；这不是车身可用宽度。
宽 0.35 m 的含 padding 矩形正对门洞时，总几何余宽分别为 0.50、0.40、
0.40 m。右侧两条横墙间通道只有 0.50 m，矩形正向总余宽 0.15 m，
膨胀梯度会重叠；软代价重叠本身不代表碰撞。上述局部截面检查不证明
完整转弯路线可执行，仍须观察门口朝向、车尾扫掠和实际导航结果。

此前 0.30 m 小于轮轴参考点的矩形外接半径约 0.367 m，Smac 会记录
computeCircumscribedCost / optimized non-circular collision checking 提示。
上游 Jazzy 的 GridCollisionChecker 在预筛选阈值无效时仍执行矩形轮廓
碰撞检查，主要代价是失去快速预筛选。日志中的此类 ERROR 应与无路径、
控制器无有效轨迹、未取得进展和进程崩溃分别统计。当前改为 0.375 m
满足该预筛选的半径要求；是否解决实际停滞仍须新测试验证。

## 缩小曲线原语，不缩小真实碰撞包络

旧控制集使用上游 0.5 m 曲线半径示例，包含原地转向；这个数不是差速底盘
不能原地转弯的限制。本次用未修改的 Nav2 原语生成器和固定上游提交，
默认探索重新生成 0.20 m 曲线半径、2.5 cm 网格、16 朝向的差速控制集，保留原地转向；
5 cm lattice 与配置保留为性能对照和回退选项。
生成参数与脚本分别是 `src/edgeai_navigation/config/lattice-generator.json` 和
`scripts/setup/generate-lattice.sh`，默认 rectangle profile 使用新文件。

运动学上 R=v/|ω|。角速度上限 0.65 rad/s 时，R=0.20 m 的弧线速度须
不超过 0.13 m/s；以 0.20 m/s 行进时至少需要约 0.308 m 半径。DWB 必须
减速才能跟踪更紧的弧线，不能同时要求最高线速度和任意小半径。原地转向
对应 v=0，但仍须给尾部留出真实扫掠空间。当前是可用的开发控制集，尚未
经过更新后的运动测试或实机标定，不能宣称已经找到最优半径。

圆形比较 profile 也按轮轴重新包络为至少 0.36 m 半径，保守版本 0.40 m。
这避免旧 0.25/0.30 m 圆漏掉车尾；默认仍使用矩形以保留朝向相关的通行能力。
旧覆盖率对比来自修正前配置，不代表新配置的测量结果。

## 精度应分别讨论

| 层次 | 当前设置与限制 |
|---|---|
| 地图离散精度 | 默认2.5 cm单元。理想栅格中心量化每轴最多半格、二维约1.77 cm；这不是SLAM总误差界 |
| 机器人定位精度 | 需要独立真值统计位置和朝向误差；当前没有已验证的厘米级承诺 |
| 探索到点 | xy 容差由25 cm改为15 cm，朝向0.25 rad；这是成功判据，不是测量精度 |
| 救援到点候选 | 独立配置5 cm容差，StoppedGoalChecker要求低速停车；尚未接入Task 2执行链 |
| 目标定位 | 受标记真实尺寸、内参、外参、角点、图像时刻TF和SLAM轨迹修正共同影响 |
| 救援成功 | 必须按官方机器人参考点进入救援区并满足连续停留时间，不能只依赖Nav2成功 |

开发救援区半径为18 cm，原25 cm导航容差可在区外报告成功。新增
`config/nav2_rescue_rectangle.yaml` 是Task 2接入候选：5 cm位置容差、
线/角停车阈值0.02 m/s和0.05 rad/s，朝向容差π，避免强加规则未要求的
最终朝向；规划备用终点容差同步为5 cm。救援判定与视觉末端修正仍待实现。
单独使用此候选文件时，须像运行脚本一样将相对 lattice 路径解析到配置目录。

如果救援区按同一参考点计算，保守预算应满足：

`位置接受容差 + 定位误差界 + 目标/救援区误差界 + 停车漂移界 ≤ 救援区半径`。

18 cm区减去5 cm到点容差只剩13 cm供其余误差使用，并不证明这些误差已达标。
若裁判检查车体中心、导航目标却按轮轴设置，还要补偿8.75 cm偏移；忽略
这个偏移时最坏只剩4.25 cm预算。正式裁判参考点尚未确定，须确认后做带
朝向的坐标变换；不要将轴心与车体中心混用。

1 cm padding也不是完整安全预算。需另计地图边界、定位、跟踪、尺寸安装
误差及速度相关的制动距离。加密地图或缩小padding不能替代标定。

## 后续精度闭环

先标定左右有效轮径、轮距、相机/雷达/IMU外参和时间偏移，再在独立验证
路线统计偏差、RMSE、95%误差、最大误差和最小间距。只有在存在系统性
偏差时调整参数，保留未参与标定的路线验证，避免只拟合一条路线。

目标观测使用图像时刻TF、真实黑色方块边长、重投影/多帧一致性筛选；
保留原始观测供回环后更新目标位姿。救援先导航接近，再近距离视觉修正，
最后按区域与连续停留条件独立判定。重复观测能减随机抖动，不能自动消除
外参、尺度、时间同步或单目平面位姿歧义。

当前仿真仍有临时质量/惯量，未建立实测轮径误差、编码器与电机响应、打滑
模型；IMU虽有噪声但未融合到当前定位。已验证的流程集成不能直接推导实机精度。
本次按要求不再扩展仿真，仅检查生成文件、坐标和几何约束。
