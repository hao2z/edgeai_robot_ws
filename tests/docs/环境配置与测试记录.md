## 启动与停止

在 PowerShell 中运行：

```powershell
cd D:\KTH\Competition\edgeai_robot_ws
powershell -ExecutionPolicy Bypass -File .\Start-Simulation.ps1
```

当前入口默认使用 WSLg；`-DisplayServer VcXsrv` 可选择备用显示服务。启动时会自动打开独立的仿真输出窗口和已加载环境的 ROS 命令行窗口，不额外保存日志。输出窗口在运行结束后保留，便于查看报错。不要同时启动第二份仿真。

需要运行 ROS 命令时，在另一个 PowerShell 窗口运行：

```powershell
powershell -ExecutionPolicy Bypass -File D:\KTH\Competition\edgeai_robot_ws\Open-ROS-Terminal.ps1
```

该入口会打开独立终端，进入 Pixi 环境并加载 install/setup.bash。可以直接运行 `ros2 topic list` 等命令；关闭命令行不停止仿真。

已有仿真运行时，可以另开实时监测窗口，不必重启仿真：

```powershell
powershell -ExecutionPolicy Bypass -File D:\KTH\Competition\edgeai_robot_ws\Open-ROS-Monitor.ps1
```

监测窗口显示新收到的 `/rosout` 日志（级别、节点名和消息）和每 10 秒刷新的 ROS 节点列表；节点出现不代表传感器数据一定正常。Gazebo 原生启动输出仍在仿真输出窗口查看。监测窗口按 Ctrl+C 或关闭只会结束监测，不额外保存日志。

结束仿真可在启动终端按 Ctrl+C，或从另一个 PowerShell 窗口运行：

```powershell
powershell -ExecutionPolicy Bypass -File D:\KTH\Competition\edgeai_robot_ws\Stop-Simulation.ps1
```

停止脚本会终止本次仿真的进程组。VcXsrv 服务保留供下次启动复用。启动、停止和 ROS 终端入口均已实际验证。

## 花屏定位

进行了以下对照：

| 显示路径 | 测试 | 结果 |
| --- | --- | --- |
| WSLg | 普通 X11 文字窗口 | 用户确认正常 |
| WSLg + RTX 4050 D3D12 | glxgears | 用户确认花屏 |
| VcXsrv + 相同 RTX 4050 D3D12 | glxgears | 用户确认正常且流畅 |
| VcXsrv + RTX 4050 D3D12 | Gazebo | 用户确认正常 |
| VcXsrv + RTX 4050 D3D12 | RViz | 移回屏幕内后，用户确认正常 |

对照将花屏定位到本机 WSLg 的 OpenGL 显示路径；具体属于 WSLg、驱动或它们之间的哪一处缺陷，尚未进一步确定。默认软件渲染和最初缺少 render 组权限也已发现并修正，独显启用本身没有消除 WSLg 花屏。

RViz 最初未显示的原因另外得到坐标证据：保存的 X=1920 超出 VcXsrv 当前 1536 像素桌面。修正后重启已确认窗口为 1280×720+40+40。
