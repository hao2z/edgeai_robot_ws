# 仿真窗口截图方法

2026-10-28：现行自动抓图、日志和检查流程见 [测试运行与观察](test-observation.md)。
以下是早期接口验证记录；列出的旧截图已按用户要求清理。
当前图片位于 `tests/results/runs/<时间>/screenshots/`。

2026-10-23 实测，当前原生 WSLg 下的 Gazebo 和 RViz 都可以通过 Windows 单窗口截图直接查看。

优先采用 PrintWindow，按 Windows 窗口标题匹配目标。实测可在 Gazebo 位于前台时，取得被遮挡的 RViz 完整内容，且保留 3D 渲染、雷达点、点云和相机显示；Gazebo 恢复窗口后，也能取得完整场景。无需截取其他应用。

当前推荐入口为 Capture-SimulationWindow.ps1，默认 Auto：

```powershell
powershell -ExecutionPolicy Bypass -File D:\KTH\Competition\edgeai_robot_ws\scripts\capture\Capture-SimulationWindow.ps1 -Target Gazebo
powershell -ExecutionPolicy Bypass -File D:\KTH\Competition\edgeai_robot_ws\scripts\capture\Capture-SimulationWindow.ps1 -Target RViz
```

脚本先恢复被最小化的目标窗口，尝试 PrintWindow；若返回失败或采样结果几乎全黑，则将目标置于前台，核实前台窗口句柄后使用 CopyFromScreen。输出 PNG 和截图方法、尺寸等元数据。默认输出 gazebo-auto.png 或 rviz-auto.png。

PrintWindow 是否支持后台图像取决于目标程序，单次成功不等于所有程序都支持，后台图像也可能因应用暂停渲染而陈旧。故自动像素检查只是初筛，仍须打开图片确认内容。CopyFromScreen 则读取当时实际屏幕上可见的像素，会切换焦点，可能包含悬浮菜单等覆盖内容。

此前的 Linux Qt grabWindow 返回黑图，不能用于判定 Windows 显示权限。本次 Windows 截图成功的窗口类名为 RAIL_WINDOW，表明捕获对象是 WSLg 在 Windows 上呈现的窗口。未对 Linux 黑图的具体底层机制做源码级证明。

## 已检查的证据

- rviz-printwindow.png：直接读到了机器人、雷达点、点云、相机显示及 Global Status: Ok。
- gazebo-screen.png：恢复 Gazebo 后的实际屏幕区域，包含完整围墙、三个障碍物和机器人。
- gazebo-printwindow.png：Gazebo 单窗口捕获，同样包含完整场景。
- rviz-background.png：Gazebo 前台遮挡时仍成功捕获 RViz，时间栏与初次捕获不同，表明不是简单复用此前保存的 PNG。

这是按需静态截图，没有安装后台录屏或持续监视任务。

官方接口说明：[PrintWindow](https://learn.microsoft.com/windows/win32/api/winuser/nf-winuser-printwindow)、[CopyFromScreen](https://learn.microsoft.com/dotnet/api/system.drawing.graphics.copyfromscreen)。
